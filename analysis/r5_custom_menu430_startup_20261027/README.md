# 4.30：启动切换与同次开机 SD 更新

2026-10-27。用户报告已选滤镜开机数秒后有预览，但随后几十秒不能切换；SD 换新滤镜又需重启两次。以冻结4.29为起点，仅本地改启动调度、诊断等待和自动应用重试，不操作相机、SD介质、Web或GitHub，不改历史交付或首次镜像。

代码能复现两处流程缺口：恢复旧配置后，同一个worker继续等待SD和最多30秒网格诊断，其间没有处理菜单请求；诊断还等待全部已配置滤镜的上传mask，正常只使用当前滤镜时不能满足。另一个缺口是SD保存成功后，CP容量/完整传输或初始E4执行失败没有完整的同次开机恢复；新文件可在下次启动恢复，因此符合“两次开机”反馈。未获得此次机身日志，不能据此认定唯一实机原因。

生产改动仅四个文件：`import/r5_stage413_thread.c`、`import/r5_grid420_log.c`、`import/r5_runtime_session.c`和`import/r5_filter_runtime423.c`。4.29页面、真实MID/布局/生命周期、左简写右全称、无更新及调整入口、确认后同步应用保存并核对父菜单再退出全部保留。BIN v4及CP逐字节继承4.23，包含4.22参数与网格生命周期。

SD/media等待、目录acquire失败后的无描述符等待点，以及诊断轮询中继续服务选择；文件打开、读取、提交和整bank传输期间保持单owner。双槽按各自扫描完成和有效媒体状态选用，另一个未就绪的槽不阻塞已就绪的槽。发现卡保留独立30秒预算，选卡后重新开始15秒读取预算，避免晚就绪卡只剩少量读取时间；同步原厂调用本身仍可能超过预算。

完整验证后按整个配置结构逐字节比较，包含简写、全称、CC1、block13、129点Gamma和所有1215网格字节；相同SD不重写文件，不重复上传已成功的bank。无效/缺失SD沿用已验证内部快照，合法零字节/空v4才清空。新bank完整传输最多尝试三次，失败间隔一秒并允许处理已有bank的选择；每次使用新session token隔离迟到ACK。CP已完成SEAL而ACK丢失时，原CP重用已封口bank，离线跨核专门验证同一次CP运行内恢复。全部重试失败仍不冒称应用成功。

自动启动选择遇到原生E4未就绪时，以一秒退避、最多30次恢复，不重传bank；用户明确选择绕过该退避，仍遵守原来的失败/回退和保存顺序。诊断只期待当前滤镜，关闭无需等待观察；等待诊断ACK时服务选择，session或bank改变则结束旧观察。日志仍是原厂同步Fsys，不能保证慢卡写日志期间没有额外延迟。

`run_offline430.py`是当前本地检查入口，`verify_startup430.py`绑定精确四文件差异和当前AP；不继承旧162项SD回放作为本轮执行证明。本轮执行180项双PIE SD场景，含晚20秒ready、第二卡槽挂起、相同内容及名称/网格单改、同次开机传输重试和永久失败上限；选择worker15项、诊断7项、实际AP/CP跨核30次选择和两路丢SEAL ACK恢复，以及原生菜单/对象/布局/输入回归。SD回放中的整bank ACK和嵌套选择是隔离边界，另由跨核与worker测试执行。诊断/启动退避用实际C在主机ISA执行，毫秒来自合成时钟，不是相机测速。

打包输入与功能回执见`release_tests/final_gate.json`；最终实体DAT独立签名/CRC、AP/CP提取和全部明文字节检查见`release_tests/delivery_verified.json`。最终可交付文件位于`research/r5_custom_lut/build_r5_4.30_startup_20261027/`，以该目录`verification.json`及独立交付回执为身份依据。未取得真实启动耗时、卡初始化回调覆盖、物理LCD/heap/cache/loader或ISP/JPG验收。

普通恢复启动复用旧drive时记录待核对状态；本轮epoch的新READY回调即使晚于启动scan返回，也由同一worker执行一次完整重新读取/校验/保存/应用，重复通知不重复提交。双PIE专门回放先读取旧SD内容、随后收到fresh READY并在同次开机发布新配置，无需第二个电源事件。
