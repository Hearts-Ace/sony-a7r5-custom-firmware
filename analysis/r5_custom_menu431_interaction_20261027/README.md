# R5 4.31 自定义滤镜菜单交互

用户实机反馈4.30加载速度改善，但上下移动不应用、左列表样式简陋、成功后误报“应用失败”。本目录从冻结4.30独立复制源码，仅修改menu_research/r5_filter_page425.c；启动、SD同步、worker、BIN v4、CP423及422参数/网格生命周期保持精确身份。没有相机、存储卡、Web或网络操作。

## 原因与修改

4.30把原生D9 type1c列表替换成七个String和字符标记；上下只改focus，确认才请求worker。4.31恢复原生列表背景、高亮和滚动，左侧简称、右侧全称；上下/长按/触摸移动立即请求原有完整应用及保存，成功留页，确认或回退走原生返回，已成功相同项不重复传输保存。没有更新按钮、额外保存按钮和右侧原生参数操作。

原先错误判定在worker成功之后仍刷新last_parent并读取旧map。原D9与父2D7的descriptor层级和view索引均为0；真实open销毁旧父，pop重建新父。4.31移除缓存父指针，返回前使用原生1BD55FC(MID635,scratch)核对已提交选择的实际资源解析，随后由原生pop和事件收尾1E97EF8驱动新父刷新。旧父无法存活到退出前，旧PageVM/1005留父fixture不足以证明D9行为，旧回执不代表此次实机问题通过。具体执行证据见parent_evidence/。

worker的精确CP ACK→原生E4执行完成→再次精确CP ACK→原子sidecar持久化→发布选择顺序没有改变。真实应用失败仍留页并提示重试；尚未完成保持精确serial并显示等待；原生菜单值解析异常另提示“滤镜已应用，菜单刷新待重试”，不混作应用失败。没有以LCD颜色变化替代持久化/执行完成判定。

## 原生控件与容量

主菜单D9和2D7使用native view pool0（6MiB），原type1c约640KiB，当前完整页面实际app allocator用677248字节；以原生固定66像素步长显示5行并居中滚动，边界留空，原控件产生高亮。13个选项/稀疏编号使用绝对原生索引，名称走既有UTF8资源桥，使用原厂同一行字体/样式链。

其他原生小池只有128/256KiB，进入前按真实view容量选择原七行文字fallback，防止强行构造大控件触发原厂arena断言；常用D9路径使用原生列表。style_evidence保存原厂指令、表初始化、模式/资源/高亮和当前AP组合回放。未以主机几何计算冒充机身字体/LCD验收。

## 验证边界

run_offline431.py统一运行当前AP的菜单、分配器、生命周期、名称输入、真实D9返回、新父刷新、原生列表高亮、worker、跨核及180项SD验证。测试中的低层GUI/libObj、文件/时钟、部分原厂服务均明确标为fixture。完整包需release_gate431.py、package431.py和独立verify_delivery431.py通过后方可交付；回执不从旧目录复制。
