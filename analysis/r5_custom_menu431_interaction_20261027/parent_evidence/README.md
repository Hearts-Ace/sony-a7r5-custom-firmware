# 4.31 父菜单生命周期证据

用户实机确认 4.30 加载改善，但应用后误报失败。430 的私有页在 worker 成功后，仍访问 `last_parent` 捕获的旧父 presenter、强制刷新并要求其旧 list 中的值正确，否则显示“应用失败”。此处没有区分参数事务和页面生命周期。

## 已锁定的代码问题

原 R5 屏幕表基址由 `0x5915668` 取得，实际为 `0x506bf20`，每项 `0x60` 字节。D9 的记录 `0x5071080` 与父主列表 2D7 的 `0x507cfc0` 在 `+0x18` 的 presenter 层级均为 **0**；原 1005/2ED 为 **1**。430 仅替换 D9 的两个 factory，层级保持原厂。

原生 `open_screen_ii(0x1ec5304)` 在 `0x1ec53f4` 读取新屏幕层级，`0x1ec5404–0x1ec5418` 析构同层及以上 presenter。因此实际 D9 接入先销毁父 2D7 presenter。父析构 `0x1ca2028` 进一步调用父 view 的 `VT+0x18` 清理参数和控件。缓存旧地址不能证明对象仍存活；430 在关闭前对旧父 map 的访问不成立，存在读过期参数的风险。

旧 `replay_native_1005_push_pop423.py` 使用层级 1 的 2ED，正确证明了 **1005** 会保留父 presenter；该证据不能移用于层级 0 的 **D9**。旧 `PageVM.open()` 直接准备理想父对象并创建自定义页，没有执行 D9 的真实原生 open，因此未捕获此次问题。旧回执保留，不追改。

## 正确的恢复和更新链

原生 `close_screen_ii(0x1ec557c)` 弹出实际屏幕栈；D9 退出时父已不存在，因此在 `0x1ec5828` 经 `0x1e97948` 重新构造 2D7 presenter。事件处理器 `0x1ec670c` 收尾在 `0x1ec7428` 调用 `0x1e97ef8`。后者遍历 manager 的 `+0x338` presenter 表，对当前屏幕以 paint=1 调用 `VT+0x10`（`0x1e97fc4`）；父 vtable `0x58c1508+0x10` 指向 `0x1d90de8`，进而执行 `0x1bc4190 → 0x1bc3f64` 填充新父列表。

列表值使用原生 `0x1bd55fc(MID, scratch)`，其中 MID 为 635；它通过 `0x1bc8eb8` 与 descriptor getter/原行资源解析取得当前短名称资源。可在关闭前用至少 `0x2e8` 字节 scratch 调此函数并检查返回值为 `R5_FILTER_SHORT_RESOURCE + 已提交选择`，不需要任何旧父对象。此检查验证原生显示值来源；worker 的精确命令、CP ACK、原厂 E4、原子保存等事务检查仍需独立通过。

无需更改全局 D9 层级，也无需在 factory 中强制绘制父页。由原生 pop 重建父，再按原生事件收尾更新它，符合真实对象生命周期。

## 原生视图池索引

`0x1e97948` 读取屏幕记录 `+0x10`（`0x1e97988`），并在 `0x1e97990` 调 `0x182ae14(index)` 选择 view pool。D9 与 2D7 的该字段均为 0；2ED 为 1。原生回放直接执行此 factory，记录的调用也分别为 **0、0、1**。因此主菜单和 D9 的常用路径都是 view pool 0。这与 `+0x18` 的 presenter 层级为不同字段，不能混用。

## 回放边界与复用

运行 `replay_parent431.py` 默认读取当前 `../ap/appFw.so`，输出 `parent431_verified.json` 并绑定完整 AP SHA256。两个 PIE 地址、三种更低层屏幕共 6 案例：真实 D9 open/pop 证实父析构及重新构造；随后执行原生事件收尾的 presenter 遍历和原生值生产，0–12 共 78 个值正确；旧父 list 用毒值标记且未被更新；另直接执行关闭前解析函数，结果同样正确。调用原生 `0x1e97948` 核对三屏的真实 view pool 参数。

实际 OS 事件循环没有运行。`0x1ec7428 → 0x1e97ef8` 通过当前 AP 原指令静态绑定，调用目标显式执行。控制器/显示分配/析构通知使用 fixture，新父参数表为按原字段准备的独立合成存储。该回放覆盖实际原生生命周期和资源解析算法，不证明机身 LCD 时序、字体或完整实机交互。完整 AP 改变后需重跑，不得仅重写散列。
