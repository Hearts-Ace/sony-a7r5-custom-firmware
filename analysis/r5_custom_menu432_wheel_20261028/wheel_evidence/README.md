## 规范事件与接入

原厂D9 dispatcher `0x1a6d8cc` 首先调用 `0x1b2932c` 和 `0x1b29374` 拆分事件。规范拨轮族为 `0x02050000`；低位子码0–5由 `0x594eb70 → 0x3c43548` 的int16表选member索引16–21，再从 `0x598a540 → 0x57ed3f0` 取16字节member记录。六项adjust均为0，直接函数指针如下。

| 规范事件 | 原厂handler | 原厂行为 | 自定义页建议 |
| --- | --- | --- | --- |
| `0x02050000` | `0x22083b4` | 设置direction=1，调用`0x2207fe0`，再传`+1`至`0x2207480` | 下一个可用配置，应用/保存并留页 |
| `0x02050001` | `0x22083d0` | 设置direction=0，调用`0x2207fe0`，再传`−1`至`0x2207480` | 上一个可用配置，应用/保存并留页 |
| `0x02050002` | `0x2207dd4` | 进入原厂参数状态/操作分支 | 吞掉，右侧参数控件已删除 |
| `0x02050003` | `0x2207e98` | 进入原厂参数状态/操作分支 | 吞掉，右侧参数控件已删除 |
| `0x02050004` | `0x1a62ebc` | 调用`0x1b2bffc(message,0x2050000,2,scene)`重投事件 | 按`+1`直接处理一次并吞掉，避免重复重投 |
| `0x02050005` | `0x1a62e8c` | 调用`0x1b2bffc(message,0x2050001,2,scene)`重投事件 | 按`−1`直接处理一次并吞掉，避免重复重投 |

`2050/2051`两handler不解引用message；每个规范事件固定一步，没有从message读取方向或步数。`2054/2055`仅将message原指针传给重投入口，并读取controller `+0x178`作为scene。实际机身上哪个旋钮产生哪组事件、顺逆时针硬件方向、加速/掉事件率没有实时采集，不将规范列表方向等同物理硬件方向。

私有输入族过滤应覆盖`0x02050000`：活动页、pending精确请求收尾、退页残留输入均应一致处理，防止轮转从未覆盖的default掉回原厂Look setter。原生创意外观页仍走原dispatcher。未知205子码应吞掉，不能臆测成列表移动；标准上下/触摸现有交互保持。

## 原始01/04事件别名边界

`0x1b2932c/374`对01/04前缀分别查两个原始常量表；规范事件直接掩码拆分。按相邻表边界枚举01的890项和04的850项，没有映射到205族的条目，因此不新增未经证实的01/04 wheel别名。这个结果仅限这两个表，不证明所有底层硬件输入或上游转换均已调查。

脚本对两种PIE偏移执行原厂dispatcher：12例核对六个handler分发；12例用空/有效/未映射message核对固定`+1/−1`；12例核对`2054/5`重投的四个参数。原始mutation `0x2207480`和queue `0x1b2bffc`为观测停止点，不执行原厂设置写入/事件队列。共36例；只在`native_wheel432.json`实际生成且`passed=true`时可引用通过。
