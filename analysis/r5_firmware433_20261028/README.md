# R5 4.33：升级参数保留、R6 ST、Fn注册及AWB

本目录从冻结4.32源码建立4.33／BCD3304。成品位于
`research/r5_custom_lut/build_r5_4.33_color_fn_20261028/`；只有最终
`release_tests/delivery_verified.json`通过才确认离线交付。
原始备份、历史固件及4.32源码／回执不改；本轮无相机或远端发布操作。

四项需求的独立证据分别位于`preservation/`、`color/`、`fn/`。

- 使用用户指定上游的generic BK4模板保留方法，补全全部R5地区模板及`backup.sum`，沿用原生升级迁移。FL2／FL3保持当前动态B／A1／A2数据，不切换fixed-a1。
- ST照片采用R6 RAW精确反算的CC1三组48字节和block13 A1的192字节；B／A2、bank尾和视频沿用R5。Gamma可见128点及Knee／YGain／公共参数与R5相同，完整Gamma沿用R5。
- 自定义滤镜接入Fn颜色／色调候选、原生注册保存和调用通路；原生创意外观保持。普通菜单描述符+c与Fn回退图标+60均使用原创意外观图标`021C6410`，标题仍为自定义滤镜。
- AWB氛围参数由-24改为-1，白色优先由88改为112；配套参数不改。

Fn仅增加可注册项，不自动占用或替换任何Fn槽位；升级后由用户在Fn菜单设置的颜色／色调分类手动分配。默认模板中的Fn槽位不在允许修改范围内，独立模板逐字核验同时约束此边界。

固件包将使用4.33／BCD3304。打包仍从冻结原厂派生的strict4.04 TAR叠加已核对的完整组件和模板，不整体替换个人设置镜像。AP沿用4.32菜单、SD读取和参数／网格生命周期，CP无需因本次模板数据变更而新增代码补丁。

AP生产源仅`r5_filter_menu423.c`中两处图标常数变化，其余22份编译对象逐字匹配4.32。Fn原生候选表追加MID635，表内41字节不同；重链接会调整相关地址，最终RX63464／BSS136384预留不增加。`verify_delta433.py`同时核对精确源码差异、编译对象、候选表、原机前缀反向恢复与现有通路回执，不能把整个AP称为仅41字节变化。CP逐字保持423，保留422生命周期。

原生Backup迁移政策核心共72例：两份原始kernel、四种模式、三项颜色属性和六个LOOK属性；attrs8的AWB／CC1／block13取新模板，LOOK的mode5取旧值。低层属性服务与memcpy使用fixture，没有执行完整升级器。12模板独立按原始FX2供体与R6片段逐字核对，仅允许13个参数范围及BK4校验变化，`backup.sum`仅12项CRC更新。不新增AP／CP强制写回、专项Backup同步、finalizer或个人设置镜像。

CP消费证据为CC1 63例、矩阵320例、AWB336例，标准AWB112例保持；CC1调整子服务输入为声明fixture，矩阵及AWB没有helper桩。ST仅照片bank0的CC1与A1更换，原厂别名仍按原映射共用bank0；不承诺所有非ST场景不变。Gamma可见128点相同，第129点与RAW未记录部分沿用R5，不能称已恢复完整R6记录。

Fn专项证据及fixture边界见`fn/fn433_verified.json`和所绑定回执。注册handler、24槽的模型与原生影子保存／恢复可离线执行；物理BKID／eMMC提交及冷启动持久性仍待机身。调用、图标及名称使用最终AP的原生查询和控制器指令，最低层绘制／队列和服务有声明fixture，不能替代实机LCD。

`release_gate433.py`绑定最终AP、全部必需回执、四项功能来源和独立模板核验；`verify_delivery433.py`独立读取最终DAT，重新验签／CRC、篡改拒绝及全部明文字节，精确核对16个TAR替换成员。离线回放、文件系统及封装核验与实机升级、Fn显示、冷启动、预览／JPG验收分别报告。以后刷入未包含本版颜色／AWB的固件仍可能恢复其模板值。色彩结论最终追加到工作区唯一研究总结。
