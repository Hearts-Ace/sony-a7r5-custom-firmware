# 4.34 图标验证修正与完成记录

用户报告4.33菜单图标无法加载。本版纠正资源类别错误，并让Fn自定义滤镜图标查询转发到原厂Creative Look当前状态。

## 已纠正的盲点

1. 旧固定oracle `0x021c6410` 是帮助文字，不是图片；原sprite fixture未执行资源查找，因此旧通过不能证明图片可加载。
2. functionID1f2原生归一化为MID1e6；旧descriptor+0c对照不能替代真实当前行的动态图标查询。
3. 原厂完整行alias树共5591项，必须与row registry共同建立；缺失会静默命中默认图标。
4. 新oracle来自最终AP原生MID1e6同状态输出；私有MID635的完整Fn刷新、sprite参数、原始UXC图片类别和像素解码分别验证。
5. 同一presenter改变模型后刷新与原生返回后重建presenter均有独立回执，不再只测试一次固定编号传递。

## 已完成覆盖

最终AP `c61d151fd7da84896d675dd7be26a8319156598206556e6e5d50ea2da11406b3`；48次Enter、2次私有关闭、6次原生push/pop、24个命名Look动态对照、288组完整刷新tile参数、48条原生UXC图片记录/主机解码。另96个注册/影子恢复、156个候选有效性、20个候选构建、4个候选文字用例由 `../fn/` 接续。

外部资源目录的冻结manifest及全部sources/artifacts进入Fn总回执绑定；共享contract同时验证本版与原厂oracle使用的native helper逐字相同。没有连接相机，没有改写历史回执。
